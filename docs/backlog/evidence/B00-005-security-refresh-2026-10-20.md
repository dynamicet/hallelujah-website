## Payload compatibility and database boundary

Payload 3.90.0 adds the hidden `resetPasswordRequestedAt` authentication field. Types were regenerated with `payload generate:types`; the repository intentionally ignores generated payload-types.ts. The controlled CMS uses disposable PostgreSQL schema creation, with no versioned CMS schema migrations or deployed CMS database. The full disposable CMS suite exercises schema creation, synthetic authentication, access control, content transfers, and governed content workflows against the upgraded adapter.

Any retained local CMS database must acquire the new field through the existing development schema-push workflow before authentication is used. A future persisted staging/production database requires a reviewed Payload migration and backup/restore evidence before upgrade; this change does not run against those environments. The governed asset collection does not enable Payload native uploads, and no storage adapter, scheduled publishing, or form-builder plugin is configured, so those release-note migration paths do not apply. Appointment SQL migrations and database isolation remain separate.
