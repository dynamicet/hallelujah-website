## Findings

| Severity | Finding | Evidence and impact |
| --- | --- | --- |
| High | Wide visual order differs from DOM/keyboard order | Source places primary navigation before Search/Language and actions. Wide CSS places Search/Language on row 1, navigation on row 2 and actions on row 3. Sequential keyboard focus consequently moves down, back up, then down through the header. |
| High | Compact disclosure does not own the specified menu composition | Only `PrimaryNavigation` is inside the popover. Search, Language, Emergency and Appointment remain outside; the closed 320 px header exposes substantially more than identity, Menu and Emergency. |
| Medium | Required forced-compact state is absent | CSS always selects wide layout at the wide breakpoint; the component has no explicit generic mode for Amharic or configured expanded-label navigation. |
| Medium | Identity naming includes an English-only token | ``aria-label={`${brandName} home`}`` constructs an accessible name outside the governed locale contract. |
| Medium | Existing regressions cannot detect these defects | Checks cover tree count, semantics, visibility, target size and interaction behavior but do not compare visual and Tab order, assert compact membership, exercise wide forced-compact mode, or reject hard-coded identity naming. |
